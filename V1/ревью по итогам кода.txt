## A1. Не учитываются decimals токена и стейблкоина

### Сейчас

В `scanner/scanner.py`:

```python
base_amount_wei = int(settings.BASE_AMOUNT_USD * Decimal(10**18))
```

То есть бот всегда считает, что у стейблкоина 18 знаков.

В `services/profit_calculator.py`:

```python
token_decimals: int = 18
stablecoin_decimals: int = 18
```

Scanner не передаёт реальные decimals.

### Должно быть

Для каждого пула нужно знать:

```text
token_decimals
stablecoin_decimals
```

И использовать их:

```text
stable_amount_raw = base_amount_usd * 10 ** stablecoin_decimals
token_amount = dex_amount_out / 10 ** token_decimals
```

### Почему

USDT и USDC имеют разные decimals:

| Сеть | USDT | USDC |
|---|---:|---:|
| Ethereum | 6 | 6 |
| BSC | 18 | 18 |
| Polygon | 6 | 6 |
| Arbitrum | 6 | 6 |

Если использовать 18 для USDT/USDC на Ethereum, бот попытается процитировать swap на сумму в триллионы раз больше реальной.

Это полностью ломает:

- quote;
- gross profit;
- net profit;
- сигналы.

### Как реализовать

1. Создать сервис:

```text
services/token_meta_service.py
```

2. Добавить класс `TokenMetaService`:

```python
class TokenMetaService:
    async def get_decimals(self, network: str, token_address: str) -> int:
        ...
```

3. Использовать ERC20 ABI:

```python
from abi.erc20 import ERC20_ABI
```

4. Кэшировать decimals:

```python
self._cache: dict[tuple[str, str], int] = {}
```

5. В `pool_refresh_task.py` после discovery добавлять в `pools_cache.json`:

```json
{
  "network": "ETHEREUM",
  "token_address": "0x...",
  "stablecoin_address": "0x...",
  "token_decimals": 18,
  "stablecoin_decimals": 6
}
```

6. В `scanner.py` заменить:

```python
base_amount_wei = int(settings.BASE_AMOUNT_USD * Decimal(10**18))
```

на:

```python
stablecoin_decimals = pool["stablecoin_decimals"]
base_amount_raw = floor_to_wei(settings.BASE_AMOUNT_USD, stablecoin_decimals)
```

7. В `profit_calculator.py` передавать:

```python
token_decimals=pool["token_decimals"]
stablecoin_decimals=pool["stablecoin_decimals"]
```

8. Добавить тесты:

- USDC decimals = 6;
- token decimals = 18;
- amount raw считается правильно;
- profit calculator правильно конвертирует amount_out.

## A2. Scanner использует только Direction A

### Сейчас

В `scanner/scanner.py` есть только:

```python
amount_out = await adapter.quote_exact_input(
    network=network,
    pool_address=pool_address,
    token_in=stablecoin_address,
    token_out=token_address,
    amount_in=base_amount_wei,
)
```

Это направление:

```text
stable → token на DEX
```

Затем вызывается:

```python
result_a = await self._profit_calculator.calculate_direction_a(...)
```

Direction B не сканируется.

### Должно быть

Для каждого пула нужно проверять оба направления:

```text
Direction A:
wallet stable → DEX buy token → MEXC sell token → wallet stable

Direction B:
wallet stable → MEXC buy token → DEX sell token → wallet stable
```

### Почему

В плане явно указано:

```text
Прибыль считается как полный round-trip:
wallet → DEX → MEXC → wallet
wallet → MEXC → DEX → wallet
```

Если проверять только Direction A, половина арбитражных возможностей теряется.

### Как реализовать

1. В `scanner.py` внутри `process_pool` после Direction A добавить Direction B.

2. Рассчитать количество токена для покупки на MEXC:

```python
token_amount = settings.BASE_AMOUNT_USD / mexc_price_usd
```

3. Конвертировать в raw amount:

```python
token_amount_raw = floor_to_wei(token_amount, token_decimals)
```

4. Сделать quote:

```python
dex_stable_out = await adapter.quote_exact_input(
    network=network,
    pool_address=pool_address,
    token_in=token_address,
    token_out=stablecoin_address,
    amount_in=token_amount_raw,
)
```

5. Вызвать:

```python
result_b = await self._profit_calculator.calculate_direction_b(...)
```

6. Если `result_b["signal"] is True`, записать сигнал с:

```python
direction="MEXC_BUY_DEX_SELL"
```

7. Добавить тесты:

- Direction A вызывается;
- Direction B вызывается;
- если оба прибыльные, пишутся два сигнала;
- если Direction B убыточный, сигнал не пишется.

## A3. Неправильный quote asset в сигналах

### Сейчас

В `scanner.py`:

```python
mexc_price_usd = self._price_service.get_price(token_coin, "USDT")
if mexc_price_usd is None:
    mexc_price_usd = self._price_service.get_price(token_coin, "USDC")
```

Но дальше:

```python
await self._write_signal(
    network, pool, token_coin, "USDT",
    result_a, mexc_price_usd, amount_out,
)
```

То есть даже если цена взята из `TOKENUSDC`, сигнал всё равно пишется как `USDT`.

### Должно быть

Сигнал должен использовать реальный quote asset:

```python
mexc_quote_asset = "USDT" или "USDC"
```

И этот quote asset должен соответствовать:

- цене на MEXC;
- стейблкоину в пуле;
- полю `mexc_symbol`.

### Почему

Иначе сигнал содержит неверные данные:

```json
{
  "mexc_quote_asset": "USDT",
  "mexc_symbol": "TOKENUSDT"
}
```

хотя цена была взята из `TOKENUSDC`.

Это опасно для анализа и будущего исполнения.

### Как реализовать

1. Добавить в `pools_cache.json` поле:

```json
"stablecoin_coin": "USDC"
```

2. В `pool_refresh_task.py` изменить SQL:

```sql
SELECT
    p.network,
    p.token_address,
    p.stablecoin_address,
    p.pool_address,
    p.dex,
    ma.coin AS token_coin,
    sc.coin AS stablecoin_coin
FROM pools p
LEFT JOIN mexc_assets ma
    ON ma.contract_address = p.token_address
   AND ma.network = p.network
LEFT JOIN stablecoins sc
    ON sc.address = p.stablecoin_address
   AND sc.network = p.network
```

3. В scanner использовать:

```python
quote_asset = pool.get("stablecoin_coin")
if not quote_asset:
    quotes_failed += 1
    return

mexc_price_usd = self._price_service.get_price(token_coin, quote_asset)
```

4. Убрать fallback `USDT -> USDC`, если пул привязан к конкретному стейблкоину.

5. В сигнале писать:

```python
mexc_quote_asset=quote_asset,
mexc_symbol=f"{token_coin}{quote_asset}",
pool_stablecoin_coin=quote_asset,
```

6. Добавить тест:

- пул USDC;
- цена есть только по `TOKENUSDC`;
- сигнал имеет `mexc_quote_asset="USDC"`.

## A4. MEXC withdraw/deposit fees не передаются в расчёт

### Сейчас

`ProfitCalculator.calculate_direction_a` имеет параметры:

```python
mexc_withdraw_fee_usd: Decimal = Decimal("0")
mexc_deposit_fee_usd: Decimal = Decimal("0")
```

Scanner их не передаёт.

Поэтому расчёт всегда использует ноль.

### Должно быть

Для Direction A:

```text
DEX buy token
→ transfer token to MEXC
→ sell token on MEXC
→ withdraw stable from MEXC
```

Нужно учитывать:

```text
MEXC withdraw fee for stablecoin
MEXC deposit fee if any
MEXC trading fee
DEX network fee
slippage
```

Для Direction B:

```text
MEXC buy token
→ withdraw token from MEXC
→ sell token on DEX
```

Нужно учитывать:

```text
MEXC withdraw fee for token
MEXC deposit fee if any
MEXC trading fee
DEX network fee
slippage
```

### Почему

Если не учитывать withdraw fee, бот будет показывать прибыльные сигналы, которые в реальности убыточны.

Например:

```text
Gross profit: $0.80
Withdraw fee: $1.20
Net profit: -$0.40
```

Без комиссии сигнал ложный.

### Как реализовать

1. Добавить в `FeeService` методы:

```python
async def get_mexc_withdraw_fee_usd(
    self,
    coin: str,
    network: str,
    token_price_usd: Decimal,
) -> Decimal:
    ...
```

2. Использовать данные из таблиц:

```text
mexc_assets
stablecoins
```

Поле:

```text
withdraw_fee
```

3. Формула:

```text
withdraw_fee_usd = withdraw_fee_coin_amount * token_price_usd
```

Для стейблкоина:

```text
withdraw_fee_usd = withdraw_fee_coin_amount * stablecoin_price_usd
```

4. Для Direction A:

- брать withdraw fee стейблкоина;
- передавать в `calculate_direction_a`.

5. Для Direction B:

- брать withdraw fee токена;
- передавать в `calculate_direction_b`.

6. Если данных о комиссии нет:

```python
warning = "mexc_withdraw_fee_unknown"
```

и использовать консервативное значение или skip.

7. Добавить тесты:

- withdraw fee = 1 token, price = 2 USD → fee = 2 USD;
- stablecoin withdraw fee = 1 USDT → fee ≈ 1 USD;
- если fee неизвестна, добавляется warning.

## A5. DEX pool fee: риск двойного учёта или отсутствия учёта

### Сейчас

В `FeeBreakdown` есть:

```python
dex_pool_fee_usd: Decimal = Decimal("0")
```

Но `FeeService` её не заполняет.

V2/V3 adapters возвращают `amount_out` из on-chain quote.

### Должно быть

Нужно явно определить:

```text
DEX quote уже включает pool fee
или
DEX quote не включает pool fee
```

И не допускать двойного учёта.

### Почему

Для Uniswap V2/V3:

- `getAmountsOut` обычно уже учитывает комиссию пула;
- `quoteExactInputSingle` тоже возвращает amount out после комиссии пула.

Если отдельно вычесть pool fee, прибыль будет занижена.

Если quote не учитывает fee, а бот её не вычтет — прибыль будет завышена.

### Как реализовать

1. В `dex/base_adapter.py` добавить контракт:

```python
quote_includes_pool_fee: bool = True
```

2. Для V2/V3 установить:

```python
quote_includes_pool_fee = True
```

3. В `FeeService` не добавлять `dex_pool_fee_usd`, если quote уже включает fee.

4. В документации и в сигнале добавить поле или комментарий:

```text
dex_pool_fee_included_in_quote=True
```

5. Если используется reserve fallback, проверить, что формула уже вычитает fee:

```python
amount_in_with_fee = amount_in * (10000 - fee_bps)
```

Это хорошо.

6. Добавить тесты:

- V2 quote не вычитает pool fee повторно;
- V3 quote не вычитает pool fee повторно;
- reserve fallback учитывает fee один раз.

## A7. On-chain V3 factory discovery имеет неправильное ABI-кодирование fee

### Сейчас

В `discovery/onchain_factory_source.py`:

```python
fee_hex = format(fee_bps * 100, "012x")
data = (
    "0x1698ee82"
    + token_address[2:].zfill(64)
    + stablecoin_address[2:].zfill(64)
    + fee_hex
)
```

`fee_hex` имеет длину 12 hex-символов.

### Должно быть

`uint24` в ABI кодируется как 32-байтное слово:

```python
fee_hex = format(fee_bps * 100, "x").zfill(64)
```

### Почему

Solidity ABI требует, чтобы каждый параметр занимал 32 байта.

Сейчас calldata получается короче, чем нужно:

```text
selector 4 bytes
address 32 bytes
address 32 bytes
fee 6 bytes instead of 32 bytes
```

RPC-вызов может возвращать ошибку или пустой результат.

Это ломает on-chain fallback discovery.

### Как реализовать

1. Открыть:

```text
discovery/onchain_factory_source.py
```

2. В методе `_check_v3_factory` заменить:

```python
fee_hex = format(fee_bps * 100, "012x")
```

на:

```python
fee_hex = format(fee_bps * 100, "x").zfill(64)
```

3. Добавить unit-тест:

```python
def test_v3_factory_calldata_length():
    token = "0x" + "1" * 40
    stable = "0x" + "2" * 40
    fee_bps = 5

    fee_hex = format(fee_bps * 100, "x").zfill(64)
    data = (
        "0x1698ee82"
        + token[2:].zfill(64)
        + stable[2:].zfill(64)
        + fee_hex
    )

    assert len(data) == 2 + 8 + 64 * 3
```

4. Проверить, что fee tiers правильные:

```text
1 bps -> 100
5 bps -> 500
25 bps -> 2500
30 bps -> 3000
100 bps -> 10000
```

## A8. Refresh удаляет старые пулы, если новых найдено ноль

### Сейчас

`PoolRefreshTask._run_refresh_inner` пишет напрямую в active DB:

```python
conn.execute("DELETE FROM pools;")
```

Если discovery нашёл 0 пулов, таблица `pools` останется пустой.

### Должно быть

Если:

```text
old_pools > 0
new_pools == 0
```

то нужно сохранить старые пулы или пометить их stale, но не удалять.

### Почему

Ноль новых пулов может означать:

- DexScreener временно недоступен;
- GeckoTerminal rate limit;
- RPC ошибка;
- временная проблема сети.

Удаление рабочих пулов остановит scanner.

В `storage/repository.py` уже есть защита:

```python
if active_has_pools and temp_pools == 0:
    atomic_replace_skipped
```

Но она не используется, потому что refresh пишет напрямую.

### Как реализовать

1. В `PoolRefreshTask._run_refresh_inner` перед `DELETE FROM pools` получить старое количество:

```python
old_pools_count = conn.execute("SELECT COUNT(*) FROM pools;").fetchone()[0]
```

2. Если `written == 0` и `old_pools_count > 0`:

- не удалять старые пулы;
- обновить только `mexc_assets` и `stablecoins`;
- записать warning:

```python
logger.warning("pool_refresh_kept_stale_pools: old=%d new=0", old_pools_count)
```

3. Добавить поле в `refresh_log`:

```text
status = "completed_with_stale_pools"
```

4. Добавить тест:

- в DB есть 5 пулов;
- discovery возвращает 0;
- после refresh пулы остаются;
- assets/stablecoins обновляются.

## A9. Refresh не делает backup перед заменой данных

### Сейчас

`BackupManager` существует.

`StateRepository` получает `backup_manager`.

Но `PoolRefreshTask` не вызывает:

```python
backup_manager.create_backup()
```

### Должно быть

Перед успешной заменой данных нужно делать backup:

```text
data/state/backups/active_YYYYMMDD_HHMMSS.sqlite3
```

Хранить последние 5.

### Почему

В плане:

```text
Backup before atomic replace.
Keep newest 5.
Delete older.
```

Если refresh повредит данные или запишет плохие пулы, нужна возможность откатиться.

### Как реализовать

## A10. Web3 создаётся заново на каждый quote и не имеет rate limit

### Сейчас

В `main.py`:

```python
def web3_factory(network: str):
    rpc_url = resolve_rpc_url(network)
    return AsyncWeb3(AsyncWeb3.AsyncHTTPProvider(rpc_url))
```

Каждый вызов создаёт новый `AsyncWeb3`.

В adapters:

```python
w3 = self._web3_factory(network)
```

То есть на каждый quote создаётся новый provider.

### Должно быть

Нужен кэш Web3-инстансов:

```python
self._web3_cache: dict[str, AsyncWeb3] = {}
```

И каждый RPC-вызов должен проходить через rate limiter.

### Почему

Сейчас:

- создаются лишние HTTP-сессии;
- нет ограничения RPC rate limit;
- можно быстро упереться в Alchemy/public RPC лимиты;
- возможны утечки ресурсов.

### Как реализовать

Вариант для младшей модели — минимально безопасный.

1. Создать:

```text
clients/web3_manager.py
```

2. Класс:

```python
class Web3Manager:
    def __init__(self, rate_limiters: dict[str, SimpleRateLimiter]):
        self._cache: dict[str, AsyncWeb3] = {}
        self._rate_limiters = rate_limiters
```

3. Метод:

```python
def get_web3(self, network: str) -> AsyncWeb3 | None:
    if network in self._cache:
        return self._cache[network]

    rpc_url = resolve_rpc_url(network)
    if not rpc_url:
        return None

    w3 = AsyncWeb3(AsyncWeb3.AsyncHTTPProvider(rpc_url))
    self._cache[network] = w3
    return w3
```

4. В adapters перед contract call вызывать:

```python
await self._rate_limiter.acquire()
```

5. В `main.py` заменить `web3_factory` на `web3_manager.get_web3`.

6. В shutdown закрыть HTTP-сессии, если возможно, или хотя бы очистить кэш.

7. Добавить тест:

- повторный вызов `get_web3("ETHEREUM")` возвращает тот же объект;
- если RPC URL нет, возвращается None.

```python
def get_adapter(self, network: str, dex_id: str, pool_version: str | None = None):
```

5. Если `pool_version` известен:

- искать registry entry с этой версией;
- не использовать вслепую alias `[v2, v3]`.

6. Если `pool_version` неизвестен:

- использовать detector;
- если не удалось определить, вернуть None и warning.

7. Добавить тесты:

- `pancakeswap + v2` → V2Adapter;
- `pancakeswap + v3` → V3Adapter;
- неизвестная версия → None.

## C8. Scanner блокирует event loop через `time.sleep`

### Сейчас

```python

```

Это синхронный sleep внутри async цикла.

### Должно быть

Либо убрать retry, либо использовать:

```python
await asyncio.sleep(0.5)
```

### Почему

`time.sleep` блокирует весь event loop.

В это время:

- не работают RPC;
- не обновляется GUI;

2. Упростить:

```python
def _load_pools_json(self):

            return json.load(f)
    except FileNotFoundError:
        return []
    except json.JSONDecodeError:
        logger.warning("pools_cache_invalid")
        return []
```

3. Если нужен retry, сделать метод async:

```python
async def _load_pools_json_async(self):
    await asyncio.sleep(0.5)
```

4. Добавить тест:

- нет файла → [];
- битый JSON → [];
- валидный JSON → list.

### P0-1. Alchemy API ключ виден в логах

**Сейчас (из лога):**
```
httpx: HTTP Request: POST https://bnb-mainnet.g.alchemy.com/v2/ALCHEMY_KEY_1_REDACTED "HTTP/1.1 200 OK"
```

```
GET https://api.mexc.com/api/v3/capital/config/getall?timestamp=...&signature=b3669eb797cf...
```

**Должно быть:**
```
httpx: HTTP Request: POST https://bnb-mainnet.g.alchemy.com/v2/***MASKED*** "HTTP/1.1 200 OK"
```
Или httpx-логи полностью отключены.

**Почему:**
В плане (раздел 24, utils/logging.py) прямо сказано: *"URLs with keys are masked before logging"*. Функция `mask_url` существует, но не применяется к httpx-логам. httpx логирует на уровне `INFO` через свой logger, минуя `mask_url`.

**Как реализовать (для junior):**

1. Открыть `utils/logging.py`, в `setup_logging()` добавить:
```python
logging.getLogger("httpx").setLevel(logging.WARNING)
```
Это отключит INFO-логи httpx (URL, status). Ошибки (WARNING/ERROR) останутся.

2. Альтернативно — оставить INFO, но добавить фильтр:
```python
class MaskUrlFilter(logging.Filter):
    def filter(self, record):
        if hasattr(record, 'msg') and isinstance(record.msg, str):
            record.msg = mask_url(record.msg)
        return True

logging.getLogger("httpx").addFilter(MaskUrlFilter())
```

3. Для MEXC signature — в `clients/mexc_client.py` не логировать signed URL. httpx WARNING достаточно.

4. Проверка: запустить бот, убедиться что в логе нет `/v2/I0pM` и `signature=`.

### P0-2. Decimals: amount_in завышен в 10¹² раз → все сигналы ложные

**Сейчас (из лога):**
```json
{"token_coin": "RAIN", "dex_amount_out": "90006494527545687398345133",
 "net_profit_pct": "12611676.45343915757451910741", "full_cycle": true}
```
```json
{"token_coin": "ARB", "dex_amount_out": "6421177549960300964022461",
 "net_profit_pct": "5336335.751648162397598315021"}
```

В `scanner/scanner.py`:
```python
base_amount_wei = int(settings.BASE_AMOUNT_USD * Decimal(10**18))
# = 10 * 10^18 = 10^19
```

USDC на Ethereum имеет **6 decimals**. Реальный amount_in должен быть:
```
10 * 10^6 = 10_000_000
```
Но бот передаёт `10^19`. Это в **10¹³ раз больше**. DEX quote возвращает астрономический amount_out.

Для RAIN: `90006494527545687398345133 / 10^18 = 9×10⁷` токенов × $0.014 = **$1.26M** "прибыли" на $10.

**Должно быть:**
```python
stablecoin_decimals = pool["stablecoin_decimals"]  # 6 для USDC/USDT на ETH
base_amount_raw = int(settings.BASE_AMOUNT_USD * Decimal(10 ** stablecoin_decimals))
# = 10 * 10^6 = 10_000_000
```

**Почему:**
USDT/USDC decimals различаются по сетям:
- Ethereum: USDT=6, USDC=6
- BSC: USDT=18, USDC=18
- Polygon: USDT=6, USDC=6
- Arbitrum: USDT=6, USDC=6

Без реальных decimals **каждый** сигнал на Ethereum/Polygon/Arbitrum ложный.

**Как реализовать (для junior):**

1. Создать `services/token_meta_service.py`:
```python
class TokenMetaService:
    def __init__(self, rpc_client_factory):
        self._rpc = rpc_client_factory
        self._cache: dict[tuple[str, str], int] = {}

    async def get_decimals(self, network: str, address: str) -> int:
        key = (network, address.lower())
        if key in self._cache:
            return self._cache[key]
        rpc = self._rpc(network)
        # ERC20 decimals() selector = 0x313ce567
        result = await rpc.eth_call(to=address, data="0x313ce567")
        decimals = int(result, 16)
        self._cache[key] = decimals
        return decimals
```

2. В `pool_refresh_task.py` после discovery, для каждого пула запросить decimals токена и стейблкоина. Записать в `pools_cache.json`:
```json
{"token_decimals": 18, "stablecoin_decimals": 6}
```

3. В `scanner.py` заменить:
```python
# БЫЛО:
base_amount_wei = int(settings.BASE_AMOUNT_USD * Decimal(10**18))
# СТАЛО:
sc_dec = pool.get("stablecoin_decimals", 18)
base_amount_raw = int(settings.BASE_AMOUNT_USD * Decimal(10 ** sc_dec))
```

4. В `profit_calculator.py` передавать реальные decimals:
```python
token_amount = dex_amount_out / Decimal(10 ** token_decimals)
```

5. Тест: USDC 6 decimals, base $10 → amount_in = 10_000_000. Не 10^19.

### P0-3. V2 router getAmountsOut игнорирует pool_address → одинаковые quotes

**Сейчас (из лога):**
4 разных пула GOLD(PAXG)/USDC на Ethereum вернули **идентичный** amount_out:
```
pool 0x5ae1... → 1148491659446597574
pool 0xcc70... → 1148491659446597574
pool 0xb431... → 1148491659446597574
pool 0xc581... → 1148491659446597574
```

Аналогично LINK (2 пула), UNI (3 пула), PEPE (3 пула), SHIB (2 пула).

В `dex/v2_adapter.py`:
```python
amounts = await router.functions.getAmountsOut(amount_in, path).call()
```
`path = [USDC, PAXG]`. Router ищет пару **сам**, игнорируя `pool_address`. Если на DEX одна пара USDC/PAXG — все 4 "пула" дают одинаковый результат.

**Должно быть:**
Для V2 использовать `pool_address` напрямую:
1. Запросить `getReserves()` + `token0()` из **конкретного** пула.
2. Рассчитать amount_out по формуле constant product с fee.
3. Router `getAmountsOut` использовать только как fallback, и логировать что pool_address проигнорирован.

Для V3: quoter уже привязан к fee tier конкретного пула, но нужно убедиться что `pool.functions.fee()` вызывается для **конкретного** pool_address.

**Почему:**
Если 4 пула дают одинаковый quote, бот:
- Тратит 4× RPC calls впустую.
- Генерирует 4 одинаковых сигнала.
- Не может выбрать пул с лучшей ликвидностью.
- В реальном trading отправил бы swap на пул с нулевой ликвидностью.

**Как реализовать (для junior):**

1. В `V2Adapter.quote_exact_input` **сначала** пробовать reserves из конкретного пула:
```python
async def quote_exact_input(self, network, pool_address, token_in, token_out, amount_in):
    # 1. Try specific pool reserves FIRST
    result = await self._quote_from_reserves(network, pool_address, token_in, token_out, Decimal(amount_in))
    if result > 0:
        return result
    # 2. Fallback to router (warn: pool_address ignored)
    logger.warning("v2_router_fallback: pool_address=%s ignored", pool_address)
    return await self._quote_from_router(network, token_in, token_out, amount_in)
```

2. В `_quote_from_reserves` кэшировать `token0()` (не меняется):
```python
self._token0_cache: dict[str, str] = {}
```

3. Тест: два разных pool_address → два разных (или одинаковых, если reserves равны) результата. Но вызовы идут к **разным** контрактам.

```python
self._web3_cache: dict[str, AsyncWeb3] = {}

def web3_factory(network: str):

    rpc_url = resolve_rpc_url(network)
    if not rpc_url:
```

```python
for w3 in self._web3_cache.values():
```

```python
fee_hex = format(fee_bps * 100, "064x")  # 64 hex chars
```
Но в production коде — `"012x"`.

**Должно быть:**
```python
fee_hex = format(fee_bps * 100, "x").zfill(64)
```

**Почему:**
Calldata короче ожидаемого → RPC возвращает ошибку или пустой результат → V3 пулы не находятся через onchain factory.

**Как реализовать (для junior):**
1. Открыть `discovery/onchain_factory_source.py`, метод `_check_v3_factory`.
2. Заменить `"012x"` на `.zfill(64)`.
3. Тест: `len(fee_hex) == 64`.
